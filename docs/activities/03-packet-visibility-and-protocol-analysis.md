# Activity 03 — Packet Visibility and Protocol Analysis

## Purpose

Capture normal Modbus/TCP traffic generated by the provided simulation and explain what a request and matching response show about process state.

## Tasks

1. Confirm the canonical student source and the exact loopback-only capture point with the instructor. Use the Ubuntu loopback interface (`lo`) and the documented Modbus/TCP port only.
2. Start the normal simulation and an authorized read client as described in the Student Lab Guide. Do not run an abnormal demonstration during this baseline capture.
3. Save a short, labeled PCAP/PCAPNG from your own VM. Avoid capturing unrelated traffic.
4. In Wireshark, identify one request and matching response. Explain relevant endpoint/port, transaction or protocol identifiers, function code, address/value fields and result as visible in your capture.
5. Correlate the decoded value with the register map and dashboard observation. State what the capture proves and what it does not prove.
6. Stop the capture and processes, then follow evidence-handling instructions.

## Evidence to submit

A learner-created PCAP/PCAPNG; annotated request/response screenshots; a short packet analysis tied to the normal baseline; and a log entry with capture method and recovery.

## Safety boundary

Capture only the isolated VM’s loopback traffic for the supplied lab. Do not monitor other interfaces, networks or learners. Do not include secrets or unrelated network data in the submission.
